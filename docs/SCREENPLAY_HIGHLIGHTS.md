# 剧本工作稿荧光笔

本分支 `feat/screenplay-highlights` 从 main `5074c0e` 创建，只实现标注。没有合并、改写或依赖 PR #11 的备份修复：未更改 app/page、备份入口、恢复事务、构建版本端点、全局 CSS、package.json 或 Supabase schema/RLS。两项功能分别验收。

## 使用

1. 在“剧本工作台 → 正文编辑”的工作稿中拖选任意文字。
2. 点“荧光笔”，选择黄色、绿色、粉色、蓝色；也可先填写可选备注。
3. 原生选区会保留，取消文本选区后可以看到荧光颜色。同一范围再次选色会修改该条颜色，不重复建立。
4. 展开编辑器下方的“标注 N 条”，修改颜色、备注，选择对应文字或取消单条标注。
5. “隐藏全部标注 / 显示全部标注”仅改变本场正文的显示偏好，不删除数据。其他场景保留各自标注和显示偏好。

支持多处范围和不同颜色相互重叠。重叠处显示最近选用的颜色，各条仍独立保存；取消上层标注会显露下面的颜色。备注最多 300 个 UTF-16 字符。

## 输入与显示分离

编辑器仍是已有原生纯文本 textarea，没有 contenteditable 或富文本格式。鼠标、键盘、复制粘贴、浏览器原生撤销/重做和中日文输入法由浏览器处理。荧光笔按钮只在鼠标左键按下时防止焦点丢失，不拦截输入快捷键或右键菜单。

背景层独立渲染、aria-hidden、pointer-events:none。正文、光标、选区和输入法字形保持原生；背景层只画颜色。组合输入阶段暂时隐藏荧光背景，提交后再对齐，避免未提交字形让背景错位。复制工作稿、生成外部修改提示或导出文字均不附带颜色代码、HTML 或备注。

背景层复制字体、字距、行高、padding、tab-size 等布局属性；统一关闭两层的字偶距/连字差异，按 textarea 的实际 clientWidth/clientHeight 和滚动偏移同步。ResizeObserver 支持拖动编辑器调整大小、窗口变化及滚动条宽度变化。标注划分按范围端点生成有限个显示片段，不为每个字符创建元素。

textarea 节点不会因为自动保存、标注或显示开关重新挂载。没有颜色时不进行锚点计算。换行处理区分保存文本与浏览器显示：原稿和现有 CRLF/CR 工作稿不会因为添加标注被改写；选区偏移转换至保存文本，显示层使用原生 LF。真正输入时沿用浏览器已有的纯文本换行规则。

## 文字修改与重新确认

标注单独保存 ID、范围、原文字、颜色、备注、状态及位置锚点，正文仍是原来的 string。范围采用 UTF-16，避免拆开 Emoji 代理对或 CRLF 对。

- 普通键入、粘贴、剪切、前后删除：使用原生 beforeinput 的选区和经过结果验证的精确编辑范围。范围之前的修改会平移标注；边界插入不会误涂新文字。
- AI 选段插入或替换：使用明确的工作稿目标范围，同样经过正文结果验证；不调用 AI API。
- 标注内部被修改/删除，或整版采用、多处改写、重复文字无法可靠确定位置：保留原标注与备注，标为“需重新确认”，不在正文画背景。
- 在正文选中正确文字，点对应行“用当前选区重新确认”，会保留该标注 ID、颜色和备注，并建立新的位置绑定。旧版本的同一句文字不能绕过这次人工确认，把标注跳回另一个相同句子。
- 文字撤销回到已记录的完整正文时，利用 SHA-256（按精确 UTF-16 单元编码）与原文字校验恢复位置，不仅凭同一句文字猜测。工作稿检查点和版本历史还保存位置快照，能恢复已存在同 ID 标注的历史位置。
- 手动取消的标注不会仅因文字撤销自动复活。版本快照保留当时的标注作为历史数据；加载历史正文时不会暗中覆盖当前备注或恢复已取消的标注。

每场最多 200 条标注，标注引用文本合计最多 100 万字符。每条最多 32 个位置锚点，保留初始确认位置和最近检查点。超过上限会提示整理，不自动删标注；超出历史记录能安全识别的范围时进入待确认，而不是猜测。

当前只在桌面正文编辑器绘制荧光背景；AI 对比区的文字修改仍同步维护位置，手机继续纯文本只读，数据和备份不会丢弃标注。

## 保存、版本与备份

沿用现有 IndexedDB、localStorage 镜像和存储键；没有数据库升级、清空或自动迁移。旧项目没有标注字段时原样读取。添加/备注/改色/隐藏/取消均自动保存；保存工作稿版本时也记录标注快照。

完整项目 JSON、手机快照、章节/场景回收与恢复会保留标注和版本。严格验证颜色、范围、状态、唯一 ID、锚点和备注长度；活动标注必须与当前正文对应，待确认标注不会被错误绘制。可选同步的现有序列化白名单只增加纯文字元数据，没有向 Supabase 写入或配置策略。

在另一 Preview 或正式域名打开时，本地存储相互独立。先从原站导出完整 JSON，使用副本验收；不要清理站点数据。备份导入 UI 与确认方式由 main/独立 PR #11 决定，本 PR 不带入其修复。高清原图和视频仍需自行备份。

## 测试与 Safari 验收

- 逻辑：精确范围、四种颜色/重叠、重复文字、Unicode/Emoji、CRLF、插入/删除/AI 替换、文本撤销、重新确认、版本、JSON/快照/回收恢复、旧七资产构造样本、严格验证及大文本基准。
- 浏览器：真实鼠标拖选、原生 DOM 和选区保留、纯文本复制、改色/备注/隐藏/取消、实际输入和 AI 选段/整版采用、待确认/撤销、滚动/尺寸同步、组合输入事件保护、CRLF、刷新和另一浏览器导入 JSON。
- Chromium：`npm run test:auth:e2e`。认证仅用本地替身，SQL 仅用 PGlite 内存；未调用付费服务或真实用户数据。
- WebKit 专项：先 `npx playwright install webkit`，再 `node tests/run-auth-e2e.mjs --config=playwright.highlights-webkit.config.ts`。该配置与 PR #11 的配置相互独立。WebKit 下载被当前执行环境出口策略 403 拦截，不能声称已运行 WebKit 或真实 Safari。

必须在真实 Mac Safari 使用备份副本检查：中文/日文输入法、Command+A/C/V/X、Command+Z/Shift+Command+Z、右键复制粘贴、页面缩放、拖动编辑器大小与滚动后高亮对齐。自动化组合输入事件只是输入保护回归，不代替系统输入法；Linux WebKit 也不等于 macOS Safari。
