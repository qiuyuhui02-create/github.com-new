# aikari 本地备份与恢复

本版从已合并 PR #10 的 main 开发。没有数据库迁移、AI 调用、云端存储或收费服务；不更改剧本/分镜的编辑区。

## 一键备份

每个桌面模块上方和手机查看页提供“一键备份”；原“导出项目”和设置里的“导出 JSON 备份”使用同一完整导出流程。

JSON 保留当前单项目的剧本、章节（含整章/场景回收站）、原稿、AI 手动候选、人工工作稿、定稿、版本与撤销历史、分镜和关联 ID、资产和版本、视频 Prompt 与生成版本、任务、日程、工时、心情/私人日记、相对路径索引以及 `previews` 中已保存的小缩略图。不筛掉旧内容、不改 ID。进行中的计时在导出副本中暂停，当前页面的计时不变。

**JSON 不打包外部原始高清图片、视频、剪辑工程或 SSD 内容。** 素材硬盘仍需单独备份。旧项目若原本含内嵌图片，会原样保留，不暗中删除；丢失的原件/预览不会被伪造。

Safari 和普通网页下载接口只能确认文件已生成并交给浏览器，不能知道用户是否取消下载或最终保存成功。因此：

1. 点击“一键备份”，立即下载文件，不弹出额外确认。
2. 状态栏显示“已生成下载”的时间。
3. 检查“下载”文件夹、文件名和大小，确认保存后点击状态栏“文件已保存”。
4. “此设备最近成功导出（已确认保存）”显示这次文件生成时间。未确认下载不会消除提醒；没有浏览器文件落盘校验的虚假承诺。

记录按本机工作空间/登录账号隔离，只留在本地，不放进项目 JSON，不计作创作修改。导入文件自带的导出时间不更新本机备份记录。首次启用后满 **3 天**没有已确认备份，或距上次已确认备份满 3 天时，会在状态栏温和提醒；不弹窗、不暂停编辑。元数据存储失败会提示，项目数据不因此改写。

## 导入：先预览，再明确替换

桌面在“云端设置 → 项目备份 → 导入项目备份到本地”选择 JSON；手机沿用“导入 Mac 项目快照”。两者共用预览和恢复流程，**本地备份导入不调用 Supabase**。

预览显示项目数量（当前格式为 1 个）、名称、活动章节/场景、分镜、资产、缩略图、Prompt、视频任务、日程任务、回收内容、备份导出时间和项目最后更新时间。旧 JSON 没有时间时显示未知，不使用文件修改日期冒充备份时间。

界面明确提示这是**整体覆盖当前设备的一个本地项目，不是新增或合并**。确认前不写项目或计时；“取消导入”、Esc 或点击遮罩关闭均不覆盖。确认按钮为“确认覆盖当前本地项目”。选择了其他登录工作空间或发现其他标签页更新时会停止。

原有云端手动同步/元数据上传入口独立保留，它不是本功能的本地恢复或自动备份。本次没有更改云端适配器、SQL、RLS 或生产数据。

## 失败与恢复前副本

- 先完整解析、验证结构、版本、ID、缩略图和工时格式。无效 JSON、重复 ID、不支持的格式或大于 100MB 的文件在写入前拒绝。为保证本功能导出的文件可重新导入，完整导出同样限制为 100MB；超过时不截断或删除数据。
- 支持旧的单项目 JSON、现有快照格式，以及以前异常缓存导出的 `{data, version}` 包装。多项目数组/集合暂不支持，会明确拒绝，不只导入其中一部分。
- 项目和导入前副本在同一个 IndexedDB 事务提交。存储不允许写入、事务失败或取消时，当前页面和项目保持原值；不会先清空项目。
- 原项目和恢复副本的旧 localStorage 镜像不在事务前覆盖。计时更新共用原计时锁，并用恢复日志处理意外关闭：下次读取本机项目时按事务是否提交恢复对应工时。未完成的日志无法核验时停止载入并提示，不猜测或清空。
- 成功后原件文件不动，素材绑定清除为未连接，但备份中的本地缩略图可继续显示。
- 设置中“导出上次导入前快照”可下载上一次成功导入前的副本；经同一预览导入可撤销恢复。只保留最近一份自动恢复副本，不能代替独立下载文件。失败的导入不覆盖这份副本。
- 浏览器被清理、无痕模式退出、设备损坏仍可能丢失全部本机数据。只有已保存到浏览器之外的 JSON 和原始素材备份才能保护这些情况。

## Preview 人工验收

1. 先在正式网站导出备份，另存副本；Preview 与正式域名存储独立，初始示例不表示正式数据丢失。
2. Preview 点击一键备份，确认下载后点击“文件已保存”，刷新检查时间。
3. 选择 JSON，检查摘要和覆盖范围，先取消验证项目不变，再确认恢复。
4. 核对自己的资产、日文/中文、AI 候选、定稿、版本、回收站、分镜/资产关联和缩略图。
5. 导出“上次导入前快照”，在 Preview 再导入验证可恢复原项目。
6. 手机导入同一 JSON，先预览再确认，核对快照版本/时间和只读内容。

无需新环境变量或 Supabase/Vercel 后台配置。PR 不自动合并，不修改 Production。自动化用 Linux Chromium、本地认证替身和内存数据库；真实 Mac Safari 下载/系统文件选择、低存储空间及你的真实数据仍需用备份副本验收。

## PR #11 恢复入口排查与 v2 版本核验

首页“一键备份”旁新增 **恢复备份**，直接打开系统文件选择器；设置与手机入口共用同一预览流程。所有 JSON 文件选择器同时接受 `.json` 扩展名与 JSON MIME，选择同一个文件也能再次预览。

报告中“导入将替换当前本地项目；建议先导出。系统会额外保留一份恢复前快照。是否继续？”这段原生确认文案存在于 main 的旧版 `5074c0e` 中；PR #11 的本地导入代码和构建后的客户端代码均无此旧分支。GitHub/Vercel 的成功记录只能证明某提交构建成功，不能还原用户当时打开的 Safari 页签或证明页签已加载同一提交。因此不直接把原因归为 Safari 缓存，也不要求清理站点数据。

新版在备份区域提供折叠的“恢复流程与页面版本”，显示构建提交、分支和 **v2 · 必须先预览再确认**。只读 `/api/build-info` 返回同样的三项公开构建元数据，并禁用浏览器/CDN 缓存；不返回项目、用户身份、API Key 或其他服务器环境变量。

选择文件及最终确认前都会核对页面与服务器版本；提交/分支/流程不匹配或服务器仍无新版端点时停止写入，保留当前项目，提示重新打开 PR #11 的最新 Preview。离线无法核验时，显示明确警告，仍只能通过本页 v2 预览和最终确认进行本地恢复，不要求云端服务。文件读取按请求编号隔离；取消会使旧读取结果失效，双击最终确认也不会开始两次恢复。

Safari 人工验收：

1. 先导出自己的项目备份，**不要清除网站数据、IndexedDB 或 localStorage**。
2. 从 PR #11 的最新 Vercel Preview 链接打开，避免使用正式站或 PR #10 的旧预览链接。交付链接的 `?v=提交号` 只用于重新请求页面，不改变本地存储的域名。
3. 展开“恢复流程与页面版本”，核对提交号和 `feat/local-backup-recovery` 分支，确认显示 v2。
4. 首页点击“恢复备份”，选择 JSON。必须出现页面内的“导入备份预览”，含项目/章节/场景/分镜/导出时间及覆盖范围；不应出现旧原生确认框。
5. 先取消，再选择同一 JSON，按 Esc 取消，验证内容不变。最后再选择并点击“确认覆盖当前本地项目”，检查恢复内容和导入前副本。
6. 设置入口、手机入口做相同检查；若页面版本不符，保留本地数据并重新打开正确 Preview，不要靠清理存储解决。

自动化专项在 `tests/e2e/backup-import.spec.ts`，覆盖真实文件选择器事件、重复选择同一文件、完整摘要、原生确认框零调用、取消前后全部工作空间 localStorage/IndexedDB 记录一致、最终确认、页面/服务器版本不匹配、只读端点无缓存，以及离线预览。Chromium 随完整浏览器测试运行。

可用 `npx playwright install webkit` 后运行 `npm run test:backup:webkit`，复用同一专项进行 WebKit 引擎回归，仍不等于 macOS Safari 系统文件对话框验收。本次执行环境下载 WebKit 时被网络策略以 403 拦截，因此没有声称运行了 WebKit 或真实 Safari。
