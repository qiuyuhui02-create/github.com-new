# 手动电影创作流程：不依赖 AI API

本分支从当前 main `f6f8a3b`（已合并 PR #8）创建，不包含 PR #9 的 Gemini 接口。无需新增环境变量、个人访问码、Redis、API Key 或付费服务。PR #9 保持未合并，不修改它的代码或状态。现有 `/api/agent` 仍固定关闭，保留的本地规则检查不调用 AI。

## 创建方式、目录与宽幅编辑

- **导入完整剧本**：读取 UTF-8 TXT / Markdown / Fountain，或粘贴全文。先点击“预览拆分”，逐区间检查起始行、章节/场景类型与自由名称；可增加边界或与上段合并，最后确认导入。预览阶段不保存新剧本。识别仅供参考，中文/日文、未知台词、空行和原始换行均保留；完整原文另存，不会被重命名或排序改写。章节内未分场的正文保留为开篇场景。内外景、场次、日夜识别均可在场景详情修正。
- **从零开始创作**：填写名称与简介，建立空白剧本；自由新增章节和场景，在工作稿编写。此方式原稿为空，工作稿与最终定稿独立。
- 左侧目录可双击章节名称，或使用右键/“⋯ → 重命名”；场景旁也有改名按钮。章节支持新增、复制、折叠、拖动和上下移，场景支持同章排序、拖动跨章移动，或在详情中选择所属章节。名称不会随排序改变。
- 删除章节必须经过两次确认。含场景时只能先选择另一章节接收全部场景，或取消；只有一个章节时需先取消、新建接收章节。删除场景使用可恢复回收站，原稿、定稿及历史随场景保留；有关分镜提示待复核，恢复使用原 ID。复制章节使用新的章节/场景 ID，已有分镜继续关联原场景。
- 右侧默认只显示宽幅工作稿；顶部切换“编写剧本 / AI 版本对比 / 确认定稿”。手动三个 AI 栏仅在对比模式显示。原稿、差异、历史、元数据和批量分镜入口按需展开。
- 所有编辑沿用 IndexedDB 自动保存；章节名、顺序、折叠、归属、回收站、简介和原文均进入 JSON。旧扁平场景仅虚拟显示在“未分组场景”，打开项目不会自动迁移；首次目录操作才保存章节字段。场景 ID 和分镜关联保持稳定。
- 当前每份剧本最多 500 个章节、500 个活动场景、500 个回收场景；全文 20 万字符、每场 5 万字符，本地文本文件最大 1MB。超过限制会阻止导入/新增并提示拆分；不截断原文。非 UTF-8 文件请先在本地另存为 UTF-8。大纲识别不是语义理解，务必检查预览。

## 剧本：三种独立内容 + 三个手动候选

1. **原始剧本**：导入时保留，后续粘贴或采用候选不会修改。
2. **人工工作稿**：自己编辑，或选择候选文字后点击“选中文字加入工作稿”。这会**追加**文字，保留已有内容，并建立撤销记录，不替换整份工作稿。
3. **最终定稿**：经人工合并候选并点击确认后独立保存，不自动跟随工作稿或候选变化。

ChatGPT、Gemini、Claude 是三个手动整理入口，新候选默认使用这些名称；旧项目的候选内容、来源名称和顺序原样保留，不自动重命名、重排或迁移。来源框可以自行编辑，栏目名不表示网站已调用对应模型。

**统一修改要求**在整个剧本共用，按场景复制。选择“本场原始剧本”或“本场人工工作稿”，点击“复制统一修改提示”，会复制该场内容和同一份修改要求。你自行粘贴到外部工具，再将返回结果粘贴到对应候选栏。网站不会替你登录、调用或购买外部 AI；外部服务由你自行选择。

在候选文本框用鼠标或键盘选中一段文字，再点击对应的加入按钮；也可展开“逐段采用”，逐段追加到人工工作稿。操作不会改动原稿或定稿。已有“加入人工候选”流程保留。

“撤销最近修改”针对人工工作稿，候选版本不会被误当成人工撤销目标。新增的撤销检查点随本地数据和 JSON 保存，刷新后仍能撤销。工作稿和候选内容版本有来源标记；旧版无标记历史保留，仍能手动选择“载入工作区”。达到 100 份上限时提示导出/拆分，不自动删除旧版本。

“修改差异”继续逐行比较原稿与工作稿；版本历史可人工载入，最终定稿另有历史与人工确认恢复。

## 分镜：手动创建、九宫格与排序

- 在已定稿场景点击“手动新建本场镜头”，或在分镜工作台选择已定稿场景。先打开编辑器，填写/修改后点击保存才建立镜头，取消不会新增镜头。
- 新镜头保留来源场景 ID、定稿修订号及存在的关联资产。默认画面文字来自该场定稿，镜号选择未占用的 `SH-xxx`；旧镜号不自动重排。
- 支持景别、构图、机位、运镜、时长、画面、对白、声音设计、状态与关联资产。
- 可读取外部 AI 生成的 JPG/PNG/WebP，沿用本地缩略图与素材索引机制，不调用图像生成服务，不上传原图。
- “九宫格总览”每组 9 个位置，支持翻页、编辑、前移和后移。排序只改变数组次序，不改镜头 ID/镜号，不破坏视频任务关联；时间线随顺序更新。
- 从已定稿段落批量建立文字草稿的原有按钮保留，仍由用户手动点击，无 AI 调用。

## 视频：四类参考图独立

每个镜头可建立一个或多个视频任务，记录模型名称、Prompt、时长、比例、运镜、资产、制作状态、文件相对路径、失败原因和修改意见。模型名称仅为文字记录，复制 Prompt 后由你在外部工具生成。

**首帧、尾帧、分镜图、人物参考图**是四个独立字段。每类都可登记文字引用或上传本地小预览；人物图支持多行/多张。所有新任务均为空引用，不会根据分镜图、资产图或任务切换来填充首尾帧。

可点击“仅登记此镜头的分镜图引用”，明确将该图登记为分镜参考，首帧、尾帧、人物图保持原值。替换已有单图引用需要确认；原件和旧索引不删除，已保存的历史版本不改动。

“保存生成版本”会记录当时的模型、Prompt、时长、比例、运动、资产、四类参考、状态与备注。随后修改当前任务，不影响已保存版本。旧版本没有记录过的新增字段显示“旧版本未记录此项”，不会用当前字段伪造历史。

图片只生成本地小缩略图，原始图片/视频仍由你保管。分镜图不自动成为视频首帧、尾帧。

## 数据兼容、备份与手机

- 沿用 IndexedDB 数据库版本和旧缓存键，没有自动清空、重建或迁移。旧项目缺少新增可选字段时照常读取。
- 保留既有资产 ID、版本关系、分镜和视频关联；没有初始化覆盖真实项目的逻辑。
- 修改要求、三个候选、工作稿撤销点、镜头顺序、四类参考及生成版本进入完整 JSON；预览图随原有小缩略图字典保存，不携带原始大文件。
- 手机仍默认只读，通过确认导入快照更新；可阅读统一修改要求和视频四类参考信息，显示原有版本/更新时间。
- 沿用原有可选云端的元数据白名单以保留新增文字字段，但本次没有访问或修改生产 Supabase、执行 SQL 或更改 RLS。未登录本地使用不需要云端。
- 原有日程、资产库、本地素材库、Prompt 中心、计时、心情及导入前恢复快照均保留。

## Preview 验收与发布边界

1. 先在原正式网址、原 Mac Safari 导出完整 JSON，单独保存。
2. 打开本 PR 的 Vercel Preview，在“项目与云端设置”中导入**备份副本**。Preview 与正式域名的浏览器存储独立，看到示例资产并不表示原项目丢失。
3. 核对自己的 7 个资产、历史版本、分镜关联和任务，再测试选段采用/撤销、九宫格、四类参考与 JSON 导出。
4. 可将 Preview 导出的快照传到手机确认导入，核对只读内容和时间标识。
5. 无需更改 Vercel 或 Supabase 配置。现有 PR #10 以 main 为目标，不依赖 #9；保持未合并，人工验收后再决定上线。开发期间只创建 Preview，不部署或修改 Production。

## 验证范围

运行 `npm test`、`npm run test:auth:e2e`、`npm run build`、`npm run typecheck` 和 `git diff --check`。

新增测试覆盖无损导入预览、空白创作、自由章节命名/排序/安全删除/恢复与完整备份，及旧 JSON 原样读取、七资产/旧候选来源保留、统一提示复制、选段追加/撤销/刷新、原稿与定稿隔离、定稿场景手动建镜头、九宫格与排序、外部图片本地预览、四类引用互不推断、历史快照及手机导入。浏览器使用 Chromium，默认桌面时区为 Asia/Shanghai，以避免午夜与 UTC 的日历断言偏差；真实 Mac Safari 仍需使用备份副本验收。

认证测试仅使用本地邮件替身，数据库测试仅使用 PGlite 内存，不触及生产账号或数据；七资产测试是构造样本，并非已经读取用户真实的七资产。
