# 第一阶段：跨平台本地素材库与 Windows SSD

## 最终分工

- Mac（Safari）：编辑剧本、Prompt、分镜、任务、资产文字及流程。无需连接素材盘，不要求 NTFS 写入权限。
- Windows（Chrome / Edge）：生成图片/视频、剪辑，并使用 NTFS 移动 SSD 保存原件与各版本。
- Supabase：跨设备同步文字、项目状态和资产索引。新媒体不写入 JSONB，也不上传到 Storage。

Vercel 网页不会移动、删除或覆盖 SSD 原件。使用文件选择读取目录，不依赖 `showDirectoryPicker` / `showSaveFilePicker` 持久写权限。浏览器刷新后需重新选择目录；这不影响文字编辑。尚未在真实 macOS Safari、Windows NTFS 实机联调；自动化测试使用 Chromium 和测试文件夹。

## Windows：按现有 SSD 路径登记

1. 将 SSD 接到 Windows，Chrome / Edge 打开项目；登录后先从云端载入最新元数据。
2. 打开“本地素材库”，点击“选择 SSD 项目目录（读取路径与核验）”。选择固定的**项目根目录**，不必选整个盘。
3. 网页核验已有索引，但不会自动登记未知文件，也不会推送云端。
4. 在“按 SSD 真实相对路径登记”中搜索、多选文件，设置用途及关联资产/分镜，点击“登记所选目录素材”。
5. 例如磁盘文件是 `E:\FilmProject\renders\shot-01\v2.mov`，根目录选择 `FilmProject`，索引仅保存 `renders/shot-01/v2.mov`。不保存盘符、根目录绝对路径或媒体二进制。
6. 原来的目录结构保持不变，不要求为每个文件 ID 新建目录，也不要求下载后再复制原件。
7. 已有相同路径、大小和 SHA-256 的文件只重新连接，保留原 ID、版本与关联；同路径内容不同会拒绝覆盖索引。新版本请在 SSD 另存文件后登记，选择“上一版本”；版本登记一次选择一个文件。
8. 登记仅修改浏览器中的索引，完成后手动推送 Supabase。跨设备没有实时自动合并：Mac 与 Windows 修改前都应先载入；冲突时先导出本地 JSON，再处理差异。

旧的“登记本地文件”入口仍保留。单文件选择无法知道它相对于项目根目录的位置，所以只生成建议路径并显示“已选择·位置待核验”。优先使用目录登记真实路径；旧建议路径可通过“重新定位”选择同内容文件并输入真实相对路径，无需移动原文件。

## 连接与校验状态

- **素材未连接**：当前浏览器没有绑定此文件；不能推断文件是否存在。Mac 管理端通常处于这个状态，仍可正常编辑所有文字。
- **已选择·位置待核验**：通过单文件选择读取到内容，尚未核验项目内位置。
- **已校验**：在用户选择的目录中，路径、大小和 SHA-256 一致。
- **所选目录未找到**：仅表示当前选择范围内没有此路径；可能是根目录选错，不等于原件丢失。
- **内容不符**：路径相同但内容或大小不同，不自动覆盖索引或原件。

点击“断开本次素材连接”只释放浏览器临时预览引用，不修改任何资产、索引或磁盘文件。浏览器刷新后也回到未连接状态。目录选择取消时不重置索引、不标记缺失。盘符变化后重新选择同一项目根目录，相对路径继续有效。

目录读取不执行全盘自动扫描；视频校验按 4MiB 分块，大视频可能需要较长时间。能否预览取决于浏览器和视频编码，不能预览不等于文件不存在。

## 可选目录示例

现有 SSD 目录可以直接沿用；下面只供新项目参考，不会强制迁移：

```text
FilmProject/
  assets/characters/
  assets/environments/
  assets/props/
  references/
  storyboards/
  videos/generated/
  videos/final/
  backups/
```

索引记录文件 ID、真实相对路径、名称、大小、格式、SHA-256、版本号、上一版 ID、资产/分镜 ID。操作不会重新编号既有资产或重建分镜。

## 现有资产和 JSON 备份

本次调整不自动迁移任何资产，也不操作真实数据库。保留现有 7 个资产前请导出原 JSON，核对 ID、版本和分镜关联；测试使用构造的 7 个资产样本，未读取你的真实项目。

- 原 JSON 继续可导入本地，未新增文件清单的旧格式仍兼容。
- 新 JSON 保存索引，不包含 SSD 原件；完整备份 = 最新项目 JSON + SSD 素材目录副本。
- 原有 Base64 / Storage 图片保留可读，不在载入时自动转换或删除。旧 Base64 不能作为新云端写入；需要迁移时由用户主动操作。
- 旧图片迁移包工具仍是明确点击、确认、下载、检查报告后再确认应用的流程。建议在 Windows 下载并解压到 SSD 新空目录。它不处理 4K 视频、不改写原云端文件，也不自动覆盖原索引。
- 复制或恢复素材目录请在 Windows 文件资源管理器操作，保留相对结构。先导入 JSON，再选择恢复后的项目根目录核验。Mac 不必写入 NTFS。

## SQL 与上线边界

**本次不执行或修改 `hybrid-storage.sql`，也不修改生产数据库。**已有客户端保护继续拦截 Base64、媒体 URI、绝对路径和超大元数据。

SQL 是可选的数据库端强制保护，并非本次 UI 与目录登记的运行前提。准备执行时，应先备份真实数据、检查已有资产是否含 Base64、确认迁移和新版读写正常，再在明确安排的上线窗口执行。脚本检查整个项目 JSON，旧 Base64 或超过 2MB 的项目会导致后续整项目保存被拒绝；不要在未评估旧数据前执行。

认证、RLS、版本冲突保护不变。本次不要求任何新的 Key、数据库密码、付费服务或本地辅助程序。
